语言模型

从 bigram 到神经语言模型，以及困惑度到底在说什么

约 2 周 需写代码 对应 W7–W8

前面四章的模型都只吃一个固定长度的向量。但语言是一串变长的东西， 而且同一个词在不同上下文里意思不一样。这一章要解决「怎么把序列喂给模型」， 并且建立本书后面一直要用的度量：交叉熵和困惑度。 更重要的是，你会亲手做出一个「前 Transformer 时代」的语言模型—— 论文 §1 批判的对象，正是它和它的祖先。

5.1 语言模型的定义

一个语言模型要回答的问题是：这段文本出现的概率是多少？

P(x1, x2, …, xT) = ∏t=1T P(xt | x1, …, xt−1) 自回归分解，也叫链式法则

这个等式没有做任何近似，它是概率的链式法则的恒等变形。 它的意义在于：把「整段文本的概率」拆成了 T 个「给定前文，下一个词是什么」的问题。

于是训练目标变成：对每个位置 t，最大化模型给正确答案的概率。取负对数，就是：

L = −(1/T) Σt log P(xt | x<t) 平均交叉熵（per-token cross entropy）

看到了吗？这就是第 3 章的交叉熵，只不过「类别」是词表里的 T 个候选， 「样本」是序列里的每个位置。语言模型就是一个做了 T 次的分类问题。 第一章日志里那个 1.78，就是这个式子的值。

要点

语言模型 = 在每个位置做一次「从 V 个候选里选一个」的分类。 V 是词表大小（本项目 96，GPT-3 是 50257）。所以输出层是一个 (d_model, V) 的矩阵， 它的输出叫 logits（未归一化的分数），经过 softmax 变成概率。

5.2 字符级还是词级

表 5-1　两种粒度
字符级词级

本项目选字符级，理由很直接：词表 96，嵌入层只占 6,144 个参数（总参数的 6%）。 如果换成 3 万词的词表，嵌入层就是 30000 × 64 = 192 万，直接超预算 19 倍。

陷阱

字符级的代价是序列变长。同样一段代码，字符级要几百个 token，词级只要几十个。 而注意力的计算量是 O(T²·d)——序列翻 5 倍，计算量翻 25 倍。 这是本项目把 seq_len 限制在 64 的原因，也是长文本任务必须处理的核心矛盾。

现代大模型用 BPE / SentencePiece 做折中：常见词整词保留，生僻词拆成子词。这是工程折中， 不影响你对模型结构的理解，本书不展开。

5.3 最简单的语言模型：bigram

假设下一个字符只依赖前一个字符。那么模型就是一张计数表：

P(xt | xt−1) = count(xt−1, xt) / count(xt−1)

实现只用十行：

from collections import Counter, defaultdict
import math, json

text = open("data/corpus.txt", encoding="utf-8").read()
# 用最后 10% 做验证，和 train.py 的划分保持一致
n = int(len(text) * 0.9)
train, val = text[:n], text[n:]

# ---- 训练：数数 ----
counts = defaultdict(Counter)
for a, b in zip(train, train[1:]):
    counts[a][b] += 1

def prob(a, b, k=0.1):
    """加 k 平滑：没见过的大二元组给一个很小的概率，避免 log(0)。"""
    total = sum(counts[a].values()) + k * 96
    return (counts[a][b] + k) / total

# ---- 评估：验证集上的平均负对数似然 ----
loss = -sum(math.log(prob(a, b)) for a, b in zip(val, val[1:])) / (len(val) - 1)
print(f"bigram 交叉熵: {loss:.4f}  nats/char")
print(f"bigram 困惑度: {math.exp(loss):.2f}")

跑出来交叉熵大概在 2.4–2.8 之间（取决于你的语料），困惑度 11–16。 记住这个数，它是你要打败的基线。

陷阱

不加平滑的话，验证集里只要出现一个训练集没见过的字符对，概率就是 0， log(0) = −inf，整个困惑度变成 inf。 平滑不是可选项，是让这个指标有意义的前提。这也是纯计数方法的根本弱点：它无法泛化。

5.4 从计数到神经网络

bigram 的问题很明显：它只看一个字符。

def _get_compiler(self, name):

看到 def 后面的下划线，你大概能猜到接下来是个函数名； 但如果只看前一个字符 f，信息量几乎为零。

Bengio 等人在 2003 年提出了解法，结构极其简单：

三个关键改动：

  1. 用嵌入代替 one-hot。96 维的 one-hot 乘 (96, d) 矩阵，等价于「取出第 i 行」。 所以嵌入层本质就是一张查找表，它让相似字符有相似的向量。
  2. 用固定窗口代替「只看前一个」。窗口取 8，就能看到 8 个字符的上下文。
  3. 用神经网络代替计数。模型可以泛化到没见过的组合——因为它学的是向量的连续表示，而不是离散的格子。
要点

这就是「神经语言模型」的核心思想，也是论文 §1 的背景： 用连续的向量表示 + 神经网络，取代离散计数，从而获得泛化能力。 后面从 RNN 到 Transformer 的所有演进，都是在这个框架内换「怎么读上下文」。

5.5 困惑度：让交叉熵变得可解释

交叉熵的单位是「奈特」，不直观。困惑度（perplexity）是它的指数：

PPL = eL = e−(1/T)Σ log P(xt|x<t) L 是平均交叉熵（自然对数）

它有一个极其好用的解释：

要点

困惑度 ≈ 模型每次在多少个等概率选项之间犹豫。
均匀瞎猜 96 个字符，PPL = 96。PPL = 7.67，相当于模型已经把候选缩小到 7.67 个。 降到 1 就是完美预测——但真实语言有内在随机性，PPL 永远到不了 1。

现在看第一章的日志，这些数字就有意义了：

步数lossPPL含义
14.5695.98初始化，约等于在 96 个字符里瞎猜
5002.3110.03已经学会了字符频率和常见搭配
30002.047.67学会了缩进、括号配对等局部结构

第 1 步的 4.56 几乎正好等于 ln(96) = 4.564。这不是巧合——初始化的模型输出接近均匀分布， 交叉熵就是 log(词表大小)。这是一个很好用的 sanity check：训练开始时 loss 应该 ≈ ln(V)。 如果你的初始 loss 差很远，多半是初始化或数据有问题。

5.6 怎么从模型里采样

训练完，模型给的是每个位置的概率分布。怎么选下一个字符，是一门小手艺。

温度

在 softmax 之前把 logits 除以温度 T：

pi = softmax(zi / T)
  • T < 1：分布变尖，高概率的更高，输出更保守、更重复。
  • T = 1：原始分布。
  • T > 1：分布变平，低概率的也有机会，输出更随机、更容易出错。

注意 T → 0 时退化成 argmax（永远选最可能的），T → ∞ 时退化成均匀分布。 它不改变排序，只改变「敢不敢冒险」。

Top-k 与 Top-p

温度有一个问题：它把概率质量也分给了明显不合理的候选。生成 300 个字符， 只要有一次选到荒谬的字符，整段就毁了。

Top-k 的解法是：只保留概率最高的 k 个，其余置为 −∞ 再归一化。 本项目默认 k=40。k=1 就是贪心解码——每次都选最可能的，结果是确定性的、容易陷入循环。

Top-p（核采样）是更精细的版本：按概率从高到低累加，凑够 p（比如 0.9）就截断。 好处是候选数量随分布形状自适应：模型很确定时只留几个，不确定时留很多。 

def sample_next(logits, temperature=0.8, top_k=40):
    logits = logits / max(temperature, 1e-6)

    if top_k is not None:
        v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
        logits[logits < v[..., -1, None]] = float("-inf")

    probs = torch.softmax(logits, dim=-1)
    return torch.multinomial(probs, num_samples=1)

这段就是 src/model.py 里 generate 的核心，只是那里写得更紧凑。

5.7 语料是怎么来的

打开 src/prepare_data.py，它做三件事：

  1. 遍历标准库目录，收集所有 .py 文件，跳过 test、idlelib 等目录。
  2. 截取前 6 MB，拼成一个字符串。
  3. 按字符频率取前 96 个，构成词表，写入 vocab.json。

第 3 步有个细节值得注意：按频率取前 N 个，意味着低频字符被直接丢弃。 脚本会打印覆盖率，本项目是 99.996%——也就是说，大约 0.004% 的字符在训练时被跳过了。

这 0.004% 里主要是中文注释、特殊符号、生僻的 Unicode。影响可以忽略，但你要知道它存在： 模型的输出永远只可能是那 96 个字符之一。它没法生成一个「没见过」的字符。

动手

打开 data/vocab.json，看 itos 的前 10 项。 你会发现它们是空格、e、t、s、r、a……完全符合英文文本的字符频率。 这 96 个字符的顺序，就是模型输出层的类别顺序。

5.8 完整实现：MLP 语言模型

把 5.4 的结构写出来，大约 40 行：

import torch, torch.nn as nn

class MLPLanguageModel(nn.Module):
    def __init__(self, vocab=96, ctx=8, d=32, hidden=128):
        super().__init__()
        self.ctx = ctx
        self.embed = nn.Embedding(vocab, d)          # 查找表
        self.net = nn.Sequential(
            nn.Linear(ctx * d, hidden), nn.ReLU(),
            nn.Linear(hidden, vocab),
        )

    def forward(self, idx):
        # idx: (B, ctx) → 嵌入 (B, ctx, d) → 拉平 (B, ctx*d)
        x = self.embed(idx).view(idx.size(0), -1)
        return self.net(x)                          # (B, vocab) logits

# ---- 训练 ----
model = MLPLanguageModel()
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
lossf = nn.CrossEntropyLoss()

for step in range(3000):
    x, y = get_batch(data, ctx=8, batch=64)   # x: (64,8), y: (64,)
    loss = lossf(model(x), y)
    opt.zero_grad(); loss.backward(); opt.step()

注意 forward 里那个 .view(B, -1)：它把 8 个字符的嵌入首尾拼接成一个 256 维向量。 这个「拼接」正是 MLP 语言模型的死穴——它把位置信息硬编码进了结构里： 第 1 个字符永远在 0–31 维，第 8 个永远在 224–255 维。窗口一变，权重全部作废。

这正是论文要解决的问题之一。Transformer 不用拼接，它用注意力让每个位置动态地决定看谁—— 但位置信息又必须另外想办法加进去（第 8 章的位置编码）。绕了一圈，问题没消失，只是换了个地方。

5.9 距离 Transformer 还差什么

你现在有一个能生成代码的模型了。它和 Transformer 的差距在三个地方：

问题MLP-LM 的做法Transformer 的做法在第几章
上下文长度固定窗口 8，写死注意力看全部历史6
位置信息嵌在拼接顺序里显式位置编码8
无法并行？其实能也能，且更长7

第二行是理解 Transformer 的关键。MLP 的位置信息是隐式的——藏在「谁在第几段」里， 模型没法表达「第 3 个字符和第 7 个字符有关」这种关系。注意力把这个关系显式化成了一个矩阵， 每个位置可以独立地、动态地决定关注谁。

本章要点

  1. 语言模型 = 自回归分解 + 每个位置做一次 V 类分类。训练目标就是平均交叉熵。
  2. 字符级词表小、无需处理未登录词，适合小模型；代价是序列长，注意力开销 O(T²)。
  3. bigram 是计数基线，必须加平滑，否则 log(0) 会让困惑度变成 inf。
  4. 困惑度 = eloss ≈ 「在多少个等概率选项间犹豫」。初始 loss ≈ ln(V) 是个好用的 sanity check。
  5. 温度改变分布的尖锐程度，top-k/top-p 截断长尾。二者解决的是不同问题。
  6. MLP-LM 把上下文拼接，位置信息隐式写死——这是它被注意力取代的原因之一。
