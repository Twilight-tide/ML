Chapter 7

多头注意力

拆头、拼头，以及一个必然踩到的内存坑

约 1 周 需写代码 对应 W11

上一章的注意力只有一个「视角」：它算出一个 T×T 的权重矩阵，然后按这个矩阵混合信息。 但语言里的关系不止一种——有的头该盯语法（主谓一致），有的该盯指代（它指谁）， 有的该盯局部（相邻字符）。一个 softmax 只能给出一种平均的注意力分配， 不同的关系模式会互相稀释。多头就是为此而生。

7.1 多头不是「更多的注意力」

先破除一个常见误解：多头不增加参数量，也不增加计算量。

表 7-1　单头 vs 多头，同样的 d_model=512
单头 (h=1, d_k=512)多头 (h=8, d_k=64)
WQ 形状512 × 512512 × 512（8 个 512×64 拼成）
四个投影矩阵参数4 × 512²4 × 512²
QKT 计算量T² × 5128 × T² × 64 = T² × 512
softmax 次数1 次（512 维联合）8 次（各 64 维独立）

前三行完全一样。真正的差别在第四行：单头把所有信息压进一个 softmax，多头让 8 个 softmax 各管一摊。

论文 §3.2.2 的原话是：

Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions. With a single attention head, averaging inhibits this.

翻译过来：单个注意力头会把「不同的关系模式」平均掉。 这句话是理解多头的钥匙。想象一个句子，第 3 个词既需要看第 1 个词（主语）， 也需要看第 5 个词（修饰语）。单头只能给出一个折中的权重分布；多头可以让头 A 专心看主语，头 B 专心看修饰语。

要点

多头 = 把同一个高维空间切成 h 个子空间，在每个子空间里独立地做一次「算相似度 + softmax + 加权」。 参数和算力不变，但归一化的粒度变细了。这是「正交分解」思想在注意力上的应用。

7.2 维度是怎么变的

这一节是全章最容易出错的地方。请把这张表抄在纸上。

表 7-2　多头注意力的完整维度流（B=batch, T=序列长, d=64, h=4, d_k=16）
步骤操作形状
0输入 x(B, T, 64)
1线性投影 w_q(x)(B, T, 64)
2view(B, T, 4, 16)(B, T, 4, 16)
3transpose(1, 2)(B, 4, T, 16)
4q @ k.transpose(-2,-1)(B, 4, T, T)
5softmax（最后一维）(B, 4, T, T)
6attn @ v(B, 4, T, 16)
7transpose(1, 2)(B, T, 4, 16)
8contiguous().view(B, T, 64)(B, T, 64)
9w_o(·)(B, T, 64)

第 2–3 步是「拆头」，第 7–8 步是「拼头」。注意第 3 步和第 7 步用的是同一个 transpose—— 这个操作是自逆的，转两次就回去了。所以代码里看起来像复制粘贴，其实是对的。

陷阱

第 8 步必须有 .contiguous()。原因见 7.4 节。少了它，PyTorch 会抛出 RuntimeError: view size is not compatible with input tensor's size and stride。 这是学 Transformer 时最高频的报错，你一定会遇到。

7.3 完整实现

import math, torch, torch.nn as nn, torch.nn.functional as F

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads, dropout=0.0):
        super().__init__()
        assert d_model % n_heads == 0
        self.h = n_heads
        self.d_k = d_model // n_heads
        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, T, _ = x.shape

        # 1) 投影 + 拆头：(B,T,d) → (B,T,h,d_k) → (B,h,T,d_k)
        q = self.w_q(x).view(B, T, self.h, self.d_k).transpose(1, 2)
        k = self.w_k(x).view(B, T, self.h, self.d_k).transpose(1, 2)
        v = self.w_v(x).view(B, T, self.h, self.d_k).transpose(1, 2)

        # 2) 缩放点积注意力：式(1)
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d_k)   # (B,h,T,T)
        if mask is not None:
            scores = scores.masked_fill(~mask, float("-inf"))
        attn = self.dropout(F.softmax(scores, dim=-1))

        # 3) 加权求和 + 拼头
        out = attn @ v                                       # (B,h,T,d_k)
        out = out.transpose(1, 2).contiguous().view(B, T, -1)

        # 4) 输出投影 W^O
        return self.w_o(out), attn

这 30 行和 src/model.py 第 65–94 行几乎一致。区别只在那边把 ScaledDotProductAttention 单独抽成了一个类（为了对照论文 §3.2.1），这里内联了。

7.4 contiguous 到底在解决什么

这不是 PyTorch 的怪癖，是内存布局的问题。

张量在内存里是一维数组加一组「步长」（stride），表示「沿每个维度走一步，在内存里跨多少个元素」。 一个 (B, T, h, d_k) 的连续张量，步长是 (T·h·d_k, h·d_k, d_k, 1)。

transpose(1, 2) 不搬动数据，它只是交换两个步长：

转置前 stride: (T*h*d_k, h*d_k, d_k, 1)
转置后 stride: (T*h*d_k, d_k, h*d_k, 1)   # 第 1、2 维的步长交换了

这时张量在逻辑上是 (B, h, T, d_k)，但内存里还是按原来的顺序排的。 view 要求「新形状能由连续内存直接切出来」，而现在的步长不满足这个条件，于是报错。

contiguous() 的作用是真的按新顺序复制一遍内存，之后 view 就合法了。

q = torch.randn(2, 4, 3, 16).transpose(1, 2)
print(q.shape)          # (2, 3, 4, 16)
print(q.is_contiguous())  # False
q.view(2, 3, 64)        # ✗ RuntimeError
q.contiguous().view(2, 3, 64)   # ✓
动手

reshape 是 contiguous().view 的安全版本——它会自动判断需不需要复制。 所以你也可以写 out.transpose(1,2).reshape(B, T, -1)，效果一样。 但你要知道它背后做了什么，否则调试显存问题时你会一头雾水。

7.5 多头到底学到了什么

src/visualize_attention.py 会画出每个头的注意力矩阵。你会看到：

  • 有的头关注对角线——「我自己」，这通常是在做某种身份保持或局部平滑；
  • 有的头关注上一两个位置——学到的是局部语法（比如 def 后面跟空格再跟名字）；
  • 有的头关注换行符——在代码语料里，缩进结构极其重要；
  • 有的头几乎是均匀分布——看起来没学到东西，但它可能在传递某种全局信息。

脚本还会打印每个头的注意力熵。熵低说明权重集中（这个头很「专一」），熵高说明分散。 在 2 层 4 头的模型里，你通常能看到熵的明显分化——这正是多头存在的价值。

要点

不要指望每个头都有可解释的功能。论文自己的可视化（图 3–5）也只展示了少数几个头有清晰模式， 其余大多难以命名。「多头分工」是一个倾向，不是保证。 后来甚至有工作发现，剪掉大部分头对性能影响很小。这一点第 10 章会再提。

7.6 为什么最后还要一个 W^O

拼起来的 h×dk 维向量里，各段来自不同的子空间，语义上并不同质。 直接把它们当特征用，等于假设「第 1 段的第 3 维」和「第 5 段的第 3 维」可以相加——这没有道理。

WO 的作用就是把这 h 个子空间重新混合成一个统一的表示。 它是一个 d_model × d_model 的矩阵，参数量和其他三个投影一样多。

如果去掉 WO，各头的信息永远停留在各自的子空间里，后续层无法把它们组合起来。 多头提供「分工」，WO 提供「汇总」。缺一不可。

7.7 在动手之前

这一章的代码不长，但建议你先不看书写一遍，写完再对照。判断标准很简单：

  1. 能不查资料写出维度流的 9 步；
  2. 能解释 transpose(1,2) 为什么出现两次；
  3. 知道 contiguous() 在哪一步必须加，以及为什么。

三条都过了，再往下读第 8 章。否则后面的残差和 LayerNorm 会让你更晕。

本章要点

  1. 多头的参数和计算量与「单头 d_model 维」完全相同，变的是 softmax 的粒度：1 次 → h 次。
  2. 单个 softmax 会平均掉不同关系模式；多头让不同子空间独立归一化。
  3. 拆头 = view(B,T,h,d_k).transpose(1,2)；拼头 = 反向操作 + contiguous。
  4. transpose 只改步长不搬数据，view 要求连续内存，所以要 contiguous()。
  5. WO 负责把各子空间重新混合。没有它，多头的信息无法被后续层组合。
