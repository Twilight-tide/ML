拼装与训练

掩码、权重共享、warmup，以及一个真实的 bug

约 1 周 需写代码 对应 W13

零件都齐了。这一章把它们装成一台机器，然后让它转起来。 装的过程中有三处细节容易被忽略：掩码加在哪、嵌入为什么要缩放、学习率为什么长成那个形状。 最后我会讲一个真实的 bug——它让训练看起来「模型太小」，实际上是学习率小了三个数量级。

9.1 因果掩码：为什么必须在 softmax 之前

自回归生成的核心约束是：预测第 t 个字符时，只能看到前 t−1 个。 但注意力的计算是对所有位置一次性完成的，第 1 个位置天然能「看到」第 100 个位置。 必须人为遮住。 

mask = torch.tril(torch.ones(T, T, dtype=torch.bool))
# [[1 0 0 0]
#  [1 1 0 0]
#  [1 1 1 0]
#  [1 1 1 1]]   True = 允许注意

scores = scores.masked_fill(~mask, float("-inf"))
attn = F.softmax(scores, dim=-1)

为什么是 softmax 之前？两种做法的差别很大：

做法结果
softmax 前设 −inf未来位置的 e−∞ = 0，行和自动等于 1
softmax 后置 0行和变成 0.6，不再是概率分布，需要手动重新归一化

数学上，e−∞ 精确等于 0，所以 softmax 会自动把概率质量重新分配到允许的位置上—— 这是一个「免费的」归一化。

陷阱

用 float("-inf") 而不是 -1e9。 后者在 fp16 下经过 softmax 可能留下 1e-38 量级的残留权重，虽然极小但不为 0。 更糟的是，如果一行全部被掩蔽，-inf 会得到 nan，而 -1e9 会得到均匀分布—— 前者会立刻暴露 bug，后者会静默出错。让错误显形，比让它隐藏好。

这也是为什么第一章那张注意力热图的右上角是黑的：那些位置是「未来」， 权重被强制设为 0。左下角是亮的，因为每个位置都能看到自己和所有过去。

9.2 拼装完整模型

class TinyTransformer(nn.Module):
    def __init__(self, vocab_size, d_model, n_heads, d_ff,
                 n_layers, max_len, dropout=0.1, tie_weights=True):
        super().__init__()
        self.d_model = d_model

        self.embed = nn.Embedding(vocab_size, d_model)
        self.pos = PositionalEncoding(d_model, max_len, dropout)
        self.layers = nn.ModuleList([
            DecoderLayer(d_model, n_heads, d_ff, dropout)
            for _ in range(n_layers)
        ])
        self.norm_out = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab_size, bias=False)

        # §3.4 权重共享：输出层直接复用嵌入矩阵
        if tie_weights:
            self.head.weight = self.embed.weight

        self.scale = math.sqrt(d_model)   # §3.4 嵌入缩放
        self.apply(self._init_weights)

    def _init_weights(self, m):
        if isinstance(m, nn.Linear):
            nn.init.normal_(m.weight, std=0.02)
            if m.bias is not None:
                nn.init.zeros_(m.bias)
        elif isinstance(m, nn.Embedding):
            nn.init.normal_(m.weight, std=0.02)
        elif isinstance(m, nn.LayerNorm):
            nn.init.zeros_(m.bias)
            nn.init.ones_(m.weight)

    def forward(self, idx, return_attn=False):
        B, T = idx.shape

        x = self.embed(idx) * self.scale    # §3.4
        x = self.pos(x)

        mask = torch.tril(torch.ones(T, T, dtype=torch.bool, device=idx.device))

        attns = []
        for layer in self.layers:
            x, a = layer(x, mask)
            attns.append(a)

        logits = self.head(self.norm_out(x))

        return (logits, attns) if return_attn else logits

三个细节值得单独说。

为什么嵌入要乘 √d_model

位置编码的值域是 [−1, 1]，而嵌入初始化是 N(0, 0.02²)，数值在 ±0.06 左右。 两者相加，位置信息会淹没语义信息。

乘以 √d_model 之后，嵌入的量级被抬到和位置编码相当（因为向量的 L2 范数大致随 √d 增长）。 论文 §3.4 只说了一句「we multiply the embedding by √d_model」，原因就是这个量级匹配。

为什么输出层没有 bias

因为它和嵌入矩阵共享权重。如果加 bias，就破坏了「同一套语义空间」的对称性。 而且嵌入矩阵本身没有 bias，共享的话形状也对不上。

权重共享省了多少

不共享：2 × 96 × 64 = 12,288
共享：　1 × 96 × 64 = 6,144 本项目省了一半的嵌入参数

在论文的规模下（V=37000, d=512），这一项是 1900 万参数，占总量的 29%。 共享与否，直接决定了模型能不能塞进显存。

而且它在语义上是合理的：输入和输出都是「字符的向量表示」， 用同一个空间来描述「字符长什么样」和「下一个字符可能是谁」，本来就该共享。

9.3 学习率：式(3)

论文 §5.3 的调度是全书最容易被抄错的公式：

lrate = dmodel−0.5 · min( step−0.5, step · warmup−1.5 ) 式(3)

它的形状是「先线性上升，再按平方根衰减」：

0 → 200 步
线性上升
→
200 步
峰值
→
200 → 3000 步
∝ 1/√step

用本项目的参数验算一遍（d=64, warmup=200）：

步数公式学习率日志实测
2500.125 × 250−0.57.91e−037.91e−03
10000.125 × 1000−0.53.95e−033.95e−03
30000.125 × 3000−0.52.28e−032.28e−03

三行都对得上。这是检验你有没有读懂式(3) 的最好方式——拿日志里的数字反算，看公式给不给得出同样的值。 第 10 章会让你对论文再做一次这样的验算。

warmup 到底在防什么

第 8 章说过：Post-LN 在训练初期不稳定。具体来说，训练刚开始时所有参数随机， LayerNorm 的输入方差很大，梯度方向剧烈变化。 如果这时用 5e−3 的学习率，一步就能把参数推到很糟的地方，然后越推越远。

warmup 让学习率从接近 0 开始，给模型几百步时间「找到方向」，再放开。 它不是在加速收敛，而是在避免早期发散。

9.4 Adam：为什么要两个动量

朴素梯度下降对所有参数用同一个学习率。但不同参数的梯度量级差很多—— 嵌入层的梯度可能很小，LN 的 γ 梯度可能很大。用同一个 η，要么小的学不动，要么大的炸掉。

Adam 维护两个滑动平均：

mt = β1mt−1 + (1−β1)gt　　（一阶矩，梯度的均值）
vt = β2vt−1 + (1−β2)gt2　（二阶矩，梯度的方差）

然后归一化：

θ ← θ − η · m̂t / (√v̂t + ε)

除以 √v 的作用是把每个参数的更新幅度归一化：梯度大的参数被压住，梯度小的被放大。 所以 Adam 对学习率的敏感度远低于 SGD——这也是它成为默认选择的原因。

论文用 β1=0.9, β2=0.98, ε=1e−9。注意 β2 比常见的 0.999 小， 意味着二阶矩的窗口更短，对梯度变化反应更快。这在 Transformer 上是有意的选择。

9.5 训练循环

opt = torch.optim.Adam(model.parameters(), lr=1.0, betas=(0.9, 0.98), eps=1e-9)
sched = torch.optim.lr_scheduler.LambdaLR(opt, lr_lambda)
lossf = nn.CrossEntropyLoss()

for step in range(1, cfg.steps + 1):
    x, y = get_batch(train_data)        # y 是 x 右移一位

    logits = model(x)                   # (B, T, V)
    loss = lossf(logits.view(-1, V), y.view(-1))

    opt.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()
    sched.step()

四行关键代码，每行都有理由：

  • logits.view(-1, V)：CrossEntropyLoss 要求 (N, C) 的输入和 (N,) 的标签， 所以要把 (B,T,V) 摊平成 (B·T, V)。这一步把「T 个位置」变成了「B·T 个分类样本」。
  • set_to_none=True：把梯度置为 None 而不是 0，省一次写内存。微小但免费。
  • clip_grad_norm_(1.0)：梯度裁剪。防止某个 batch 的梯度异常大，把参数一步推飞。 论文也用了这个（§5.1）。
  • sched.step()：注意顺序——先 opt.step() 再 sched.step()， 否则第一次更新用的是第 0 步的学习率。

9.6 那个真实的 bug：学习率小了 1000 倍

这是本项目第一版训练时的真事，值得完整讲一遍，因为它是「症状误导诊断」的典型。

症状：loss 从 4.57 降到 3.71 就几乎不动了。生成的文本是乱码：

def  ,
dcul" ac #nok)n
 ll.,ol)n.=s da&t pp)

看起来像「模型容量不够」或「数据不够」。但真正的原因在两行代码： 

# ✗ 有 bug 的写法
opt = torch.optim.Adam(model.parameters(), lr=1e-3)
sched = torch.optim.lr_scheduler.LambdaLR(opt, lr_lambda)

LambdaLR 的实际学习率是：

actual_lr = base_lr × lambda(step)

而 lr_lambda 返回的是论文式(3) 的值（约 2.28e−3），base_lr 又乘了 1e−3：

2.28e−3 × 1e−3 = 2.28e−6 比论文值小了整整三个数量级

修正只有一处：

opt = torch.optim.Adam(model.parameters(), lr=1.0)  # ← base_lr 设为 1
要点

这个 bug 的教训不是「LambdaLR 怎么用」，而是方法论： loss 不降时，先把论文里的关键数值算出来，和实际用的对一遍。 一算就发现差了 1000 倍，比怀疑模型容量、怀疑数据量快得多。

怀疑的顺序应该是：数值 → 数据 → 结构 → 容量。 初学者往往反过来，从「模型太小」开始怀疑，然后加参数、加数据、加层数，全部无效。

9.7 生成

@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        # 只保留最近 max_len 个 token（位置编码的窗口）
        idx_cond = idx[:, -self.pos.pe.size(1):]

        logits = self(idx_cond)[:, -1, :]      # 只要最后一个位置
        logits = logits / max(temperature, 1e-6)

        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = float("-inf")

        probs = F.softmax(logits, dim=-1)
        nxt = torch.multinomial(probs, num_samples=1)
        idx = torch.cat([idx, nxt], dim=1)

    return idx

两个细节：只取 [:, -1, :]（前面的位置已经算过了，虽然这里为了简单每次都重算）， 以及截断到 max_len（位置编码只预计算了这么多行）。

真实推理会做 KV cache：把已算过的 K、V 存起来，每步只算新的一个 token。 这样复杂度从 O(T²) 降到 O(T)。本项目为了简洁没有实现，但你应该知道它的存在—— 没有 KV cache，大模型根本没法实时对话。

9.8 现在你有了完整的一台机器

回顾一下整条链路：

token 索引 (B, T)
↓ 查表 × √d_model
嵌入 (B, T, 64)
↓ 加位置编码
× N 层：掩蔽自注意力 → 残差 → LN → FFN → 残差 → LN
↓ 输出 LN + 线性层（与嵌入共享）
logits (B, T, 96)
↓ softmax + 采样
下一个字符

这就是论文图 1 右半边，一个不多一个不少（交叉注意力除外，因为本任务没有编码器）。

本章要点

  1. 掩码必须在 softmax 之前设 −inf，这样 e−inf=0，行和自动为 1。
  2. 嵌入乘 √d_model 是为了和位置编码的量级匹配；输出层无 bias 是因为权重共享。
  3. 式(3) 先线性升、再按 1/√step 降；warmup 是 Post-LN 的稳定性补丁，不是加速技巧。
  4. Adam 用二阶矩归一化每个参数的更新幅度，所以对学习率不敏感。
  5. loss 不降时的排查顺序：数值 → 数据 → 结构 → 容量。那个 1000 倍的 bug 就是没查数值。
