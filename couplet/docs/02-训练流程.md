### 实现要点（写代码时踩到的）

1. **`keep_char` 要定义在 `build_vocab` 之前**。Python 实际能容忍
   "函数体内引用后定义的函数"（因为调用发生在运行时），但这是运气不是设计。
2. **`check()` 里 `isinstance(actual, int)` 会把 `True` 格式化成 `1`**
   （Python 中 `bool` 是 `int` 的子类）。输出的 `1` 实际是 `True`，
   判定逻辑不受影响。要修的话加一句类型判断：

```python
def check(name, actual, expected):
    ok = actual == expected
    if isinstance(actual, bool):
        shown = str(actual)                     # True / False 原样显示
    elif isinstance(actual, int):
        shown = format(actual, ",")
    else:
        shown = str(actual)
    print("  [%s] %-24s %s" % ("OK  " if ok else "FAIL", name, shown))
    return ok
```

## 阶段 M1 · 数据管道（原始设计稿）

> 以下为设计时的规格，实际实现见上方"实际结果"。保留作为对照。

### 做什么

写 `couplet/src/prepare_data.py`，把文本变成数字张量。

### 要实现的四件事

**1. 字符清洗 + 统计词表**

```
输入：过滤 1-2 字后的 train/in.txt + train/out.txt
处理：(a) 用 keep_char 过滤掉坏字（见下）
      (b) 按出现频率降序；不卡频次阈值，全部保留
输出：couplet/data/vocab.json   （格式 {"itos": {"0": "<pad>", ...}}）

期望结果：9,011 个可用字符 + 3 个特殊标记 = 9,014
```

**必须先做字符清洗**：语料里有 31 个非汉字字符，其中 21 个是垃圾
（15 个私用区字符 + 注音符号 + 兼容汉字）。详细依据见
`01-技术方案.md` §4.3。清洗规则：

```python
KEEP_PUNCT = set("，、。？！；：（）《》「」『』【】…—〇·")
KEEP_EXTRA = set("-")       # 语料里用 - - 表示破折号，必须保留

def keep_char(ch):
    """字符是否保留：汉字 + 常见标点 + 连字符。"""
    if "\u4e00" <= ch <= "\u9fff":
        return True
    if ch in KEEP_PUNCT or ch in KEEP_EXTRA:
        return True
    return False
```

**为什么 `-` 不能丢**（这是实测发现的，不是想当然）：
语料里 `- -` 表示破折号，实际用例——
```
娓 娓 道 来 - - 声 声 慢
钢 丝 绾 个 同 心 结 - - 硬 盘
```

**为什么私用区字符要丢**：看语境能确认是坏字——
```
下联: 薄 命 ㄚ 环 不 得 闲     ← ㄚ 本该是"丫"
下联: 何 须 掌 指  头 皮       ← \ue828 本该是"抓"
```

**注意顺序：先过滤 1–2 字短联，再做字符清洗，最后统计词表。**
顺序反了会有两类问题：词表留下永远用不到的位置（90 个短联专有字），
或者坏字混进词表。

```
字符集变化：9,122 → 过滤 1-2 字 → 9,032 → 字符清洗 → 9,011 → +3 标记 → 9,014
```

必须先插入三个特殊标记：`<pad>`、`<s>`、`</s>`，固定在 id 0/1/2。

**2. 脏数据过滤**

上联字数 ≠ 下联字数的样本，丢弃。
统计丢弃了多少条，记进日志。

**3. 统计长度分布**

```
上联字数的分布：最短 __、最长 __、平均 __、覆盖 99% 需要的长度 __
```

这个数字决定 `max_len`。

> **这部分我已经在 M0 阶段替你测过了**（因为参数量决策依赖它），
> 结果见 `01-技术方案.md` §4.5：
> 7 字占 47.10%、99 分位 25 字、99.9 分位 28 字、最长 32 字 → **`max_len=40`**。
>
> 你写 `prepare_data.py` 时**仍然要自己跑一遍统计**（代码要能算出来），
> 但可以拿我的数字对照——**如果对不上，说明读取方式有问题**。
> 这比"我的代码跑通了"更有说服力。

**4. 构造训练样本**

对每一条，生成三个序列：

```python
enc_input  = 上联的字 id                     # [白, 日, 依, 山, 尽]
dec_input  = [<s>] + 下联的字                # [<s>, 黄, 河, 入, 海]
dec_target = 下联的字 + [</s>]               # [黄, 河, 入, 海, </s>]
```

### 容易写错的地方

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 用 `list(line)` 切字 | 空格也被当成字符，字数翻倍 | 用 `line.split()` |
| 解码器输入/目标没右移 | 训练 loss 很快降到 0，生成时全是乱码 | 输入首位补 `<s>`，目标末位补 `</s>` |
| 词表没有 `<pad>` | 无法做填充掩蔽 | 三个特殊标记固定在 id 0/1/2 |
| 词表顺序不稳定 | 两次运行结果不一致 | 按频率降序，频率相同按字符排序 |

**第一条专门为这个数据集写的**：行内容形如 `'晚 风 摇 树 树 还 挺 '`（行尾有空格），
`list()` 会得到 13 个元素（含空格），`split()` 才是正确的 7 个。

### 关于脏数据过滤

**实测 0 条脏数据**（770,491 条全部字数相等）。但代码仍要写这道检查——
它是防御性的：既能输出"0 条"作为**证据**写进报告，也能在将来换数据集时兜住。

### M2-1 · 改造 `MultiHeadAttention`

**为什么要改**：现在的版本只能接受一个输入（自注意力：Q=K=V）。交叉注意力要能接受**两个不同的输入**。

现在的签名：

```python
def forward(self, x, mask=None):
    q = self.w_q(x)     # q、k、v 都来自 x
    k = self.w_k(x)
    v = self.w_v(x)
```

要改成：

```python
def forward(self, q_in, kv_in=None, mask=None):
    """q_in 提供 Q；kv_in 提供 K 和 V。

    kv_in=None  → 自注意力（Q=K=V=q_in）
    kv_in=encoder_out → 交叉注意力
    """
    kv_in = q_in if kv_in is None else kv_in

    B, T_q, _ = q_in.shape
    T_k = kv_in.shape[1]          # ← 注意和 T_q 可能不同！

    q = self.w_q(q_in).view(B, T_q, self.h, self.d_k).transpose(1, 2)
    k = self.w_k(kv_in).view(B, T_k, self.h, self.d_k).transpose(1, 2)
    v = self.w_v(kv_in).view(B, T_k, self.h, self.d_k).transpose(1, 2)
    ...
```

**这里有个 shape 陷阱**：`T_q`（解码器长度）和 `T_k`（编码器长度）在 seq2seq 里
**不一定相等**。`mask` 的形状必须是 `(T_q, T_k)`，不是 `(T, T)`。

对联碰巧上下联等长，所以 `T_q == T_k`——**这会掩盖 bug**。
如果只在等长数据上测，写错了也看不出来。所以 M2-5 的验证一定要用
**不等长**的假数据测一次。

**✅ 自检 M2-1**

```python
mha = MultiHeadAttention(d_model=64, n_heads=8)

# 自注意力
x = torch.randn(2, 10, 64)
out, attn = mha(x)
assert out.shape == (2, 10, 64)
assert attn.shape == (2, 8, 10, 10)

# 交叉注意力（T_q != T_k）
q = torch.randn(2, 7, 64)
kv = torch.randn(2, 13, 64)
out, attn = mha(q, kv)
assert out.shape == (2, 7, 64), out.shape      # 输出跟随 Q 的长度
assert attn.shape == (2, 8, 7, 13), attn.shape  # 注意力矩阵是 (T_q, T_k)
```

**关键理解**：输出长度 = Q 的长度；注意力矩阵形状 = `(T_q, T_k)`。

### M2-2 · 写 `EncoderLayer`

照抄 `DecoderLayer`，**删掉因果掩蔽**，并去掉交叉注意力（编码器没有它）。

```python
class EncoderLayer(nn.Module):
    def __init__(self, d_model, n_heads, d_ff, dropout):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.ffn = PositionwiseFeedForward(d_model, d_ff, dropout)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout1 = nn.Dropout(dropout)
        self.dropout2 = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        a, attn = self.self_attn(x, mask=mask)
        x = self.norm1(x + self.dropout1(a))
        f = self.ffn(x)
        x = self.norm2(x + self.dropout2(f))
        return x, attn
```

**为什么没有因果掩蔽**：编码器处理上联时要看**整句**——第 1 个字也应该知道
第 7 个字是什么。这跟解码器完全不同（解码器只能看左边，否则训练时在偷答案）。

**✅ 自检 M2-2**

```python
enc = EncoderLayer(64, 8, 256, 0.1)
x = torch.randn(2, 10, 64)
out, attn = enc(x)
assert out.shape == (2, 10, 64)

# 双向性验证：改掉最后一个位置，前面位置的输出应该变化
x2 = x.clone()
x2[:, -1, :] += 1.0
out2, _ = enc(x2)
assert not torch.allclose(out[:, 0], out2[:, 0]), "编码器应该是双向的！"
```

**最后那条是功能性验证**：如果第 0 个位置的输出**不**受最后一个位置影响，
说明你误加了因果掩蔽——那就变成了"解码器"，不是编码器。

### M2-3 · `DecoderLayer` 加交叉注意力

原来两个子层，现在三个：

```
子层 1：掩蔽自注意力       Q=K=V=解码器自己，加因果掩蔽
子层 2：交叉注意力         Q=解码器，K=V=编码器输出，不加因果掩蔽  ← 新增
子层 3：前馈
```

```python
class DecoderLayer(nn.Module):
    def __init__(self, d_model, n_heads, d_ff, dropout):
        super().__init__()
        self.self_attn = MultiHeadAttention(d_model, n_heads, dropout)
        self.cross_attn = MultiHeadAttention(d_model, n_heads, dropout)   # 新增
        self.ffn = PositionwiseFeedForward(d_model, d_ff, dropout)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)      # 新增
        self.norm3 = nn.LayerNorm(d_model)      # 原来的 norm2 变 norm3
        self.dropout1 = nn.Dropout(dropout)
        self.dropout2 = nn.Dropout(dropout)     # 新增
        self.dropout3 = nn.Dropout(dropout)

    def forward(self, x, enc_out, self_mask=None, cross_mask=None):
        # 子层 1：掩蔽自注意力
        a1, attn1 = self.self_attn(x, mask=self_mask)
        x = self.norm1(x + self.dropout1(a1))

        # 子层 2：交叉注意力（Q 来自解码器，K/V 来自编码器）
        a2, attn2 = self.cross_attn(x, enc_out, mask=cross_mask)
        x = self.norm2(x + self.dropout2(a2))

        # 子层 3：前馈
        f = self.ffn(x)
        x = self.norm3(x + self.dropout3(f))
        return x, attn1, attn2
```

**注意 LayerNorm 和 Dropout 的数量变化**：2 个 → 3 个。
漏掉一个会在拼接时 shape 对不上（或者更糟，静默跑通但结构不对）。

### M2-4 · 拼成 `Seq2SeqTransformer`

```python
class Seq2SeqTransformer(nn.Module):
    def __init__(self, vocab_size, d_model, n_heads, d_ff,
                 n_layers_enc, n_layers_dec, max_len, dropout=0.1):
        super().__init__()
        self.d_model = d_model
        self.embed = nn.Embedding(vocab_size, d_model)
        self.pos = PositionalEncoding(d_model, max_len, dropout)
        self.encoder = nn.ModuleList([
            EncoderLayer(d_model, n_heads, d_ff, dropout)
            for _ in range(n_layers_enc)])
        self.decoder = nn.ModuleList([
            DecoderLayer(d_model, n_heads, d_ff, dropout)
            for _ in range(n_layers_dec)])
        self.norm_out = nn.LayerNorm(d_model)
        self.head = nn.Linear(d_model, vocab_size, bias=False)
        self.head.weight = self.embed.weight      # 论文 §3.4 权重共享
        self.scale = math.sqrt(d_model)
        self.apply(self._init_weights)

    def encode(self, src):
        """上联 → 编码器输出。"""
        x = self.embed(src) * self.scale
        x = self.pos(x)
        mask = torch.ones(src.size(1), src.size(1), dtype=torch.bool, device=src.device)
        for layer in self.encoder:
            x, _ = layer(x, mask)
        return x

    def forward(self, src, tgt):
        """src (B, T_src) 上联；tgt (B, T_tgt) 解码器输入。"""
        enc_out = self.encode(src)

        y = self.embed(tgt) * self.scale
        y = self.pos(y)
        T = tgt.size(1)
        causal = torch.tril(torch.ones(T, T, dtype=torch.bool, device=tgt.device))
        cross = torch.ones(T, enc_out.size(1), dtype=torch.bool, device=tgt.device)

        for layer in self.decoder:
            y, _, _ = layer(y, enc_out, self_mask=causal, cross_mask=cross)
        return self.head(self.norm_out(y))
```

**三个掩蔽的区别，一定别搞混**：

| 掩蔽 | 形状 | 作用 |
|---|---|---|
| 编码器自注意力 | `(T_src, T_src)` 全 True | 上联内部随便看 |
| 解码器自注意力 | `(T_tgt, T_tgt)` 下三角 | 只能看左边 |
| 交叉注意力 | `(T_tgt, T_src)` 全 True | 下联每个位置都能看上联全部 |

```python
src2 = src.clone()
src2[:, 0] = (src2[:, 0] + 1) % 9014
out3 = model(src2, tgt)

changed = not torch.allclose(out1, out3, atol=1e-5)
print("交叉注意力连通:", changed)     # 必须是 True
```

**这两条的意义**：

- 验证 2 失败 → 掩蔽写错，模型在训练时偷看答案，训练 loss 会异常低，
  但生成时全是乱码。
- 验证 3 失败 → 交叉注意力没接上（比如 `kv_in` 传错了），编码器白算，
  模型退化成"只看下联自己"，等于没用上上联。

**这两类 bug 都不会报错**，只会让结果变差——所以必须显式测。

**✅ 验收检查点 M2**

- [ ] 参数量 = **810,496**
- [ ] 因果性 = True
- [ ] 交叉注意力连通 = True
- [ ] 用**不等长**的 src/tgt（如 7 和 5）也跑得通

## 阶段 M3 · 训练脚本

### 做什么

写 `couplet/src/train.py`。

### 要实现的

**1. 学习率（照抄论文式(3)，注意 base_lr）**

```python
scale = cfg.lr_scale / math.sqrt(cfg.d_model)
def f(step):
    step = max(step, 1)
    return scale * min(step ** -0.5, step * cfg.warmup_steps ** -1.5)

opt = torch.optim.Adam(model.parameters(), lr=1.0, betas=(0.9, 0.98), eps=1e-9)
sched = torch.optim.lr_scheduler.LambdaLR(opt, f)
```

⚠️ `lr=1.0` 不是笔误。`LambdaLR` 的实际学习率是 `base_lr × lambda(step)`，
设成 1.0 才能让实际值等于论文公式。

**2. 损失函数**

```python
lossf = nn.CrossEntropyLoss(ignore_index=pad_id)
loss = lossf(logits.view(-1, V), target.view(-1))
```

`ignore_index` 必须有，否则模型学成"一直输出填充符"。

**3. 验证函数**

除了 loss/ppl，**还要算四条规则通过率**（见 `03-验收与评价.md`）。
这样能同时看到"统计指标"和"真实质量"——你的代码生成项目证明了这两条线可以背离。

### ✅ 验收检查点 M3

- [ ] 前 100 步 loss 从 ~9.1（`ln(9014)`）稳定下降
- [ ] 学习率曲线符合预期：先升后降，峰值在 warmup 结束处
- [ ] 先跑 200 步存一个"小模型"，用它测一次推理，**不做任何检查，先能跑通**
- [ ] 训练日志写进 `results/train_log.csv`

**为什么先跑 200 步就测推理？**
训练 3 小时后的失败是最贵的。用一个 2 分钟的小模型把推理链路先跑通，
能提前发现"生成函数写错了"这类问题。

## 阶段 M4 · 推理

### 做什么

写 `couplet/src/generate.py`。

### 两种解码方式

**贪心解码**（先做这个）

```
每步取概率最高的字，直到生成 </s> 或达到长度上限
```

**集束搜索**（beam search，后做）

```
每步保留概率最高的 k 条候选路径
k=3 或 5，最后选累计概率最高的
```

集束搜索对联特别有用：**只看单步的话，"平仄"这个约束体现不出来**，
保留多条候选后，可以用规则重新打分。

### 一个重要技巧：长度约束

上联 5 个字 → 下联必须 5 个字。可以直接从输入长度算出目标长度，
**解码时强制到该长度停止**，不依赖模型自己生成 `</s>`。

这样能保证"字数相等"这条规则 100% 通过——把一条规则从"模型要学"变成"工程保证"。

### ✅ 验收检查点 M4

- [ ] 用训练过的模型对 5 个上联生成下联
- [ ] 关闭长度约束，看模型能否自己生成 `</s>`
- [ ] 用同一上联生成 5 次，观察多样性（温度 0.5 / 1.0 各试一次）
- [ ] 对比贪心 vs 集束搜索（k=3）的输出差异

## 阶段 M5 · 评价脚本

### 做什么

写 `couplet/experiments/evaluate.py`，在 test 集上跑批量评价。

**详细规则和指标口径见 `docs/03-验收与评价.md`**，这里只说流程：

```
对 test 集的 N 条（建议先 500 条）：
  1. 用模型生成下联
  2. 逐条检查四条规则
  3. 统计通过率
  4. 与"真实下联"的通过率对比（真实下联应该 100% 通过，作为参照系）
```

**"真实下联的通过率"这一步不能省**——如果真实下联自己都过不了规则，
说明是我的规则写错了，不是模型差。

### ✅ 验收检查点 M5

- [ ] 真实下联的四条规则通过率 = 100%（或接近，排除脏数据）
- [ ] 模型生成下联的通过率有明确数字
- [ ] 按"上联字数"分组统计（5 字联 vs 7 字联 表现是否不同）
