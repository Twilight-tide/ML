# 03 · 验收与评价

这份文档定义"什么算一副合格的对联"，以及怎么自动检验。

对联的好处是**规则明确**。2008 年中国楹联学会颁布《联律通则》，把规则整理成六条。
其中四条能全自动检验，两条需要人工——**这正是本项目的评价优势**。

---

## 1 六条规则，哪些能自动检验

| # | 规则 | 含义 | 能否自动 |
|---|---|---|---|
| 1 | 字句对等 | 上下联字数相等 | ✅ 直接数 |
| 2 | 词性对品 | 相同位置词性一致 | ⚠️ 需分词 + 词性标注 |
| 3 | 结构对应 | 词语结构平衡 | ❌ 需语义理解 |
| 4 | 节律对拍 | 节奏点一致 | ✅ 按位置判断 |
| 5 | 平仄对立 | 上联收仄、下联收平，节奏点平仄相反 | ✅ 查声调表 |
| 6 | 形对意联 | 内容相关但不重复 | ❌ 需人工 |

**本项目自动检验 1、4、5，加上一条工程规则"无重复字"。**

---

## 2 四条自动规则的具体做法

### 规则 1 · 字数相等

```python
def check_length(up, down):
    return len(up) == len(down)
```

**注意**：统计的是**字符个数**，但要先决定标点算不算。

数据集的格式是空格分隔的单字，`"白 日 依 山 尽".split()` 得到 5 个元素，
所以正确写法是：

```python
def to_chars(s):
    return [c for c in s.split() if c]      # 而不是 list(s)
```

**这是个真实存在的坑**：`list("白 日 依 山 尽")` 会得到 9 个元素（含空格）。
代码生成项目踩过类似的问题（词表 id 映射错位），值得警惕。

#### ⚠️ 标点必须单独处理（M1 统计时发现的）

语料里**含标点**（逗号、句号），而且**全角逗号「，」的出现次数是全语料第一**
（824,170 次，比第二名「风」的 146,389 次多 5.6 倍，M1 实测）。

例（test 集第 1 条）：

```
腾 飞 上 铁 ， 锐 意 改 革 谋 发 展 ， 勇 当 千 里 马
```

它按 `split()` 是 15 个 token，但汉字只有 12 个。

**所以 `to_chars` 要给两个版本**：

```python
def to_chars(s, drop_punct=False):
    """文本 -> 字符列表。
    
    drop_punct=False  保留标点（用于生成、词表相关判断）
    drop_punct=True   只留汉字（用于「字数相等」这条规则）
    """
    chars = [c for c in s.split() if c]
    if drop_punct:
        chars = [c for c in chars if "\u4e00" <= c <= "\u9fff"]
    return chars
```

**「字数相等」规则用 `drop_punct=True`**：
对联讲的"字"是汉字个数，标点不计数。
但**「无重复字」规则要保留标点**——标点重复不违反联律。

这个口径必须在报告里写明，否则数字对不上别人无法复现。

### 规则 2 · 无重复字

分两个层次，**上联重复的字，下联对应位置也应重复**：

```python
def check_repeat(up, down):
    """检查上下联的重复模式是否一致。"""
    up_chars = to_chars(up)
    down_chars = to_chars(down)

    # 建位置映射：每个字 -> 它出现过的位置列表
    def repeats(chars):
        pos = {}
        for i, c in enumerate(chars):
            pos.setdefault(c, []).append(i)
        return pos

    up_pos, down_pos = repeats(up_chars), repeats(down_chars)

    # 上联在同一位置重复的字，下联也要重复
    for c, idxs in up_pos.items():
        if len(idxs) > 1:
            # 上联有重复，检查下联这些位置的字是否相同
            chars_at = {down_chars[i] for i in idxs}
            if len(chars_at) != 1:
                return False
    return True
```

**简化版**（先用这个，够用）：

```python
def check_no_repeat_simple(up, down):
    """严格版：上下联内部都不出现重复字。"""
    return len(set(to_chars(down))) == len(to_chars(down))
```

两种口径都统计，**报告里注明用的是哪种**。

### 规则 3 · 平仄对立

需要一份**平仄字典**。规则：

- **平声**：普通话第一声（阴平）、第二声（阳平）
- **仄声**：第三声（上声）、第四声（去声）
- 古入声字按古韵算仄。现代普通话已把它们并入四声（「入派三声」），
  所以**不能用现代读音代替古韵口径**——本项目实测过，理由见下方「方法 D」

**关键判断点**：

```
上联末字必须是仄声
下联末字必须是平声
```

这条是死条件，先做这个。**节奏点平仄相反**（第 2、4、6 字）作为进阶检查。

获取平仄字典有四种方法。**本项目用的是 D**，理由在下面。

**方法 A**：用 `pypinyin` 库（普通话读音）

```python
from pypinyin import pinyin, Style
tone = pinyin("白", style=Style.TONE3)[0][0]     # 'bai2'
# 末位数字 1/2 → 平，3/4 → 仄
```

**方法 B**：手工整理常用字平仄表（500–1000 字）。工作量大但无依赖。

**方法 C**：查《平水韵》表（古韵，对联界认可度最高）。需要外部数据。

**方法 D（本项目采用，已在用）**：**从语料反推**。

对联规则是「上仄下平」，所以统计每个字在上下联末字的分布即可判定——
大量出现在下联末尾者为平声，上联末尾者为仄声。

实测（74 万个末字，出现 ≥20 次的 3,012 字）：
```
可判定 2,909 字（1,305 平 / 1,604 仄），仅 4% 判不出
24 个已知平仄的字（风花山天…/ 月水树地…）全部判对
占比分布呈双峰：0.0-0.1 有 1,445 字，0.9-1.0 有 1,248 字
```
代码 `src/tone.py`，产物 `data/tone_table.json`（42 KB，入库）。

**为什么不推荐方法 A**：实测对比（详见 `技术报告.md` §4.3）——

| 尺子 | 全量 4,000 副的「上仄下平」符合率 | 仅在 155 个分歧字上 |
|---|---|---|
| 语料反推（方法 D） | **96.97%** | **84.72%** |
| pypinyin（方法 A） | 90.57% | **11.72%** |

分歧的 155 字中有 144 个是入声字（一、出、发、学、国、合、及、吉……），
普通话「入派三声」把它们读到一二声，但格律里仍属仄。
11.72% 远低于随机的 50%，说明是系统性反向，不是噪声。

**结论：传统格律判据不能直接用现代汉语拼音替代。**

### 规则 4 · 末字平仄（从规则 3 拆出来单独统计）

单独统计这一条的原因：**它是最容易达成、也最有效的改进点**。

```
解码时如果知道"必须落在平声字上"，可以直接在最后一步约束采样。
```

这就是"把规则从模型要学变成工程保证"的思路。分开统计能看出这条的效果。

## 3 指标口径

### 3.1 汇总表

每条生成的下联打 4 个勾：

| 上联 | 生成下联 | 字数 | 重字 | 平仄 | 末字 |
|---|---|---|---|---|---|
| 白日依山尽 | 黄河入海流 | ✅ | ✅ | ✅ | ✅ |
| 春风送暖 | 明月照人来 | ✅ | ✅ | ❌ | ✅ |

### 3.2 三个层面的通过率

| 指标 | 定义 | 用途 |
|---|---|---|
| **单规则通过率** | 每条规则单独通过的比例 | 定位瓶颈在哪一条 |
| **全通过率** | 四条全过的比例 | 主指标 |
| **规则通过率-真实下联** | 用真实下联当参照 | **校准规则自身是否正确** |

第三个指标容易被忽略但很重要：

> 如果真实下联的通过率是 78%，那说明我的规则有问题，不是模型差。

**真实下联必须接近 100%**（排除脏数据）。达不到就先修规则，不要看模型的数。

### 3.3 分组统计

按上联字数分组（5 字 / 7 字 / 其他），看是否不同：

```
5 字联：全通过率 __%
7 字联：全通过率 __%
```

对联有"五言""七言"的传统分类，分组统计能看出模型是否偏向某类。

## 4 评价脚本的接口设计

建议这样组织（`couplet/experiments/evaluate.py`）：

```python
def to_chars(s):
    """文本 -> 单字列表。注意是 split 不是 list。"""

def rule_length(up, down):
    """规则 1：字数相等。返回 bool。"""

def rule_repeat(up, down):
    """规则 2：无重复字。返回 bool。"""

def rule_tone(up, down):
    """规则 3：平仄对立（末字 + 节奏点）。返回 bool。"""

def rule_end_tone(up, down):
    """规则 4：上仄下平。返回 bool。"""

def check_all(up, down):
    """返回 dict：{'length': bool, 'repeat': bool, 'tone': bool, 'end': bool}"""

def evaluate_batch(pairs, tag):
    """批量评价。pairs 是 [(up, down), ...]。
    返回各规则通过率 + 全通过率，并打印。"""

def main():
    # 1. 先在真实下联上跑，校准规则
    real = load_test_pairs(limit=500)
    evaluate_batch(real, "真实下联（校准用，应接近 100%）")

    # 2. 再用模型生成
    gen = [(up, model_generate(up)) for up, _ in real]
    evaluate_batch(gen, "模型生成")

    # 3. 按字数分组
    for n in (5, 7):
        subset = [(u, d) for u, d in gen if len(to_chars(u)) == n]
        if subset:
            evaluate_batch(subset, "%d 字联" % n)
```

**先跑参照组再跑实验组**——这个顺序能避免"用错误的尺子量出错误的结论"。

## 5 与代码生成项目的对照

这套评价体系和代码生成项目的 `eval_generation.py` 是同一种思路，但对联更强：

| | 代码生成 | 对联 |
|---|---|---|
| 指标 | 签名合法率、引号成对 | 字数、重字、平仄 |
| 客观性 | 中等（"合法"有歧义） | **高**（规则是行业标准） |
| 参照系 | 无 | **真实下联**（天然的 100% 基准） |
| 可归因 | 难 | **容易**（知道卡在哪条规则） |

**最后一条是关键**：如果你发现"字数 100%、平仄 45%"，那结论很明确——
模型的输出长度控制住了，但没学好声调。这比"生成的代码不太像"可操作得多。

## 6 一个重要的心态准备

82 万参数能学到什么、学不到什么，事先说清楚：

| 能力 | 预期 | 依据 |
|---|---|---|
| 字数相等 | ✅ 容易 | 可以直接工程约束，甚至不需要学 |
| 无重复字 | ✅ 中等 | 是局部规律，模型能学到 |
| 末字平仄 | ⚠️ 需努力 | 有字典后可以后处理保证 |
| 节奏点平仄 | ⚠️ 较难 | 需要位置意识 |
| 词性对品 | ❌ 难 | 需要词性知识 |
| 形对意联 | ❌ 很难 | 这是 82 万参数的上限 |

**建议的做法**：

把规则分成"模型负责"和"工程负责"两部分：

```
模型负责：生成语义合理的下联
工程负责：字数约束、末字平仄约束、候选重排
```

这样七十七万条数据 + 八十二万参数，**做出来的东西是能看的**——
而不是追求"全都学会"，结果什么都做不好。

这个思路和你代码生成项目的经验一致：
**"参数决定能不能写出签名，语料决定签名写得好不好"**——
对联就是"模型决定内容，规则决定格式"。
