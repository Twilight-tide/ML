## M0 准备数据　2026-11-15　✅

- **完成**：下载并核对数据集
- **实测数字**：
  - 文件：train/in.txt 770,491 行 / train/out.txt 770,491 行 / test 各 4,000 行 / vocabs 9,130 行
  - 总条数：774,491（train 770,491 + test 4,000）
  - 语料不同字符：9,122（过滤 1–2 字后降到 9,032）
  - **脏数据：0 条**（770,491 条全部上下联字数相等）
  - 长度分布：7 字 47.10%、5 字 10.05%、12 字 12.07%；99 分位 25 字，最长 32 字
- **遇到的坑**：
  1. 我最初给的下载命令是 bash 语法，但终端是 PowerShell——
     `&&` 不支持、`curl` 是别名（须写 `curl.exe`）、行尾 `\` 不能续行。
     浪费了一轮。→ 文档已改成 PowerShell + Git Bash 双版本。
  2. 数据集自带的 `vocabs` **没有 `<pad>`**，只有 `<s>` 和 `</s>`。
     必须自己重建词表，三个标记固定在 id 0/1/2。
  3. 词表实际 9,130 字，远超文档假设的 4,000 → **直接推翻了 50 万参数预算**。
- **怎么发现的**：
  - 先 `wc -l` 核对行数（发现上下联行数完全相等，与"14 条脏数据"的传闻不符）
  - 用 Python 逐条比对字数，确认 0 条脏数据
  - 统计字符集和覆盖率，发现全词表下 `d_model` 只能取 32（`d_k=4`，不可用）
  - 固定 81 万预算反解各档位，发现 `d_model=64` 时 `d_ff/d_model = 256/64 = 4.0`，
    与论文的 `2048/512 = 4.0` 完全一致
- **结论**：
  - 参数量从 50 万调整为 **811,840**，`d_model=64 / d_ff=256 / d_k=8`
  - 词表取全部 9,032 字（test 集 OOV 仅 6 个字，0.008%）
  - 三个决策由用户拍板：用全词表、max_len=40、过滤 1–2 字
- **产出**：`docs/01-技术方案.md` §2/§4 全部改为实测数字；
  `docs/02-训练流程.md` M0 标记完成；README 同步更新
