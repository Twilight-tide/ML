# Transformer 语言模型：参数规模、内部机制与能力边界

**实验时间**：2026 年 11 月
**代码**：`src/`（模型、训练、生成、可视化）
**产物**：`results/model.pt`（495,440 参数）、`results/train_log.csv`、`results/attention_*.png`

---

## 摘要

本项目在一个按论文架构实现的解码器-only Transformer 上，做了三组实验：

1. **参数规模扫描**（10 万 → 94 万）：测出当前语料下的最优参数规模是 50 万，94 万只比它好 1.3%，但训练慢 73% 且已出现明显过拟合。
2. **注意力层分工观察**：模型自发形成「第 1 层看局部、第 2 层看全局」的分工，用注意力熵定量验证（层 1 均值 0.61，层 2 均值 1.95）。
3. **能力边界的频率解释**：生成质量与语料中该模式的频次强相关——出现 9000 次以上的关键字（`if`/`def`/`return`）能写出语法正确的代码，出现 2000 次左右的（`class`/`import`）退化成自然语言散文。

三条结论指向同一件事：**当前模型的瓶颈不是参数量，是语料规模与分词粒度。**

## 1 项目概述

### 1.1 模型结构

按《Attention Is All You Need》实现，做自回归语言建模（只用解码器）：

| 项目 | 本模型 | 论文 base |
|---|---|---|
| 层数 N | 2 | 6 |
| d_model | 128 | 512 |
| 注意力头数 h | 8 | 8 |
| d_k = d_model/h | 16 | 64 |
| d_ff | 680 | 2048 |
| 参数量 | 495,440 | 65M |
| 分词粒度 | 字符级（词表 96） | BPE（37k） |

**保留的论文要素**：缩放点积注意力（式 1）、多头注意力（式 2）、正弦位置编码（式 3）、残差 + LayerNorm、权重共享、warmup 学习率（式 4）。

**省略的要素**：编码器与交叉注意力（任务是纯生成，无源序列）。

### 1.2 语料与训练

```
语料      Python 源码，5,668,894 训练字符 + 629,878 验证字符

序列长度  64
批大小    32

正则化    dropout 0.1 + 梯度裁剪 1.0
```

## 2 实验一：参数规模的影响

### 2.1 方法

固定数据、随机种子（42）、批大小、序列长度、训练步数（12000），只改变模型尺寸。参数量通过调整 `d_model`、`n_heads`、`d_ff`、`n_layers` 控制。

四组配置：

| 组 | d_model | 头数 | d_ff | 层数 | 参数量 |
|---|---|---|---|---|---|
| A | 64 | 4 | 232 | 2 | 100,048 |
| B | 96 | 6 | 560 | 2 | 301,024 |
| D | 128 | 8 | 680 | 2 | 495,440 |
| C | 128 | 8 | 640 | 4 | 937,216 |

### 2.2 结果

| 配置 | 参数量 | 最优 val | ppl | 最优步数 | 训练耗时 |
|---|---|---|---|---|---|
| A | 100,048 | 1.9039 | 6.71 | 10,000 | 78 s |
| B | 301,024 | 1.7683 | 5.86 | 12,000 | 80 s |
| **D** | **495,440** | **1.7270** | **5.62** | **12,000** | **77 s** |
| C | 937,216 | 1.7048 | 5.50 | 9,000 | 133 s |

相对基准 A 的提升：B +7.1%，D +9.3%，C +10.5%。

### 2.3 分析

**（1）收益递减**

```
A → B：参数 ×3.0，val 降 7.1%
B → D：参数 ×1.6，val 降 2.3%
D → C：参数 ×1.9，val 降 1.3%
```

同样的参数增长速度，收益在持续衰减。

**（2）深度比宽度贵得多**

C 与 D 宽度相同（d_model=128），只差层数（4 vs 2）：

```
层数 2 → 4：训练时间 77s → 133s（+73%）
```

原因在计算结构：宽度增加让矩阵乘变大（GPU 并行，代价低）；层数增加是**串行**的，第 2 层必须等第 1 层完成。

**（3）94 万参数已经过拟合**

C 的验证损失在 9000 步达到最低（1.7048），之后回升：

```
step  9000   1.7048   ← 最低点
step 10000   1.7210
step 12000   1.7964   ← 比 B 的最优值还差
```

train/val 差距同步扩大：

| 配置 | train | val | 差距 |
|---|---|---|---|
| A | 1.6751 | 1.9138 | 0.24 |
| B | 1.4730 | 1.7683 | 0.30 |
| D | 1.4027 | 1.7270 | 0.32 |
| C | 1.3373 | 1.7964 | **0.46** |

C 的训练损失最低，验证损失最差——典型的记忆训练集。

### 2.4 结论

**50 万是当前语料下的最优点。**

选择依据不是「最大最好」，而是性价比：94 万比 50 万多花一倍参数、多等 73% 时间，只换来 1.3% 的提升，并且已经在背答案。

用经验法则验证：50 万参数配 567 万 token，比例 1:11；94 万的比例是 1:6，低于常用的 1:20。**数据量不足时，加大参数只会加速过拟合。**

## 3 实验二：注意力层的分工

### 3.1 方法

让模型处理一段有结构的代码（`def __init__(self, config):` + 缩进的赋值语句），取出每层每个头的注意力权重矩阵，计算每行分布的熵：

```
H = -Σ p_i · log(p_i)
```

熵越低表示注意力越集中（几乎只看一个位置），越高表示越分散。

### 3.2 结果

**各头的熵**（序列长度 53，取平均）：

```
层 1：0.92  0.58  0.55  0.68  1.06  0.41  0.12  0.53    均值 0.61
层 2：1.75  1.94  2.08  1.62  1.92  1.87  2.05  2.37    均值 1.95
```

**可视化**（`results/attention_layer_avg.png`）：

- 层 1 的权重集中在紧邻前一个位置，图上是一条锐利的对角线
- 层 2 没有对角线，亮点散布在整个左下三角区域

### 3.3 分析

**（1）分工是自发形成的**

论文没有规定「浅层做局部、深层做全局」。这个结构是训练中自己形成的：局部模式（相邻字符搭配）在第一层就能解决，第二层没必要重复，于是转向更远的关系。

**同样的分工在 GPT-2、BERT 等大模型上都被观察到。** 一个 50 万参数、用 567 万字符训练的小模型，复现了这个结构。

**（2）层 1 头 7 是「前一个 token 头」**

其熵只有 **0.12**，对应图上最锐利的那条对角线——它几乎只做一件事：看紧邻的前一个字符。

这类头在真实模型中被命名为 previous-token head，是语法处理的基础组件之一。

**（3）实现正确性得到验证**

```
每行权重和    ∈ [1.000000, 1.000000]   → softmax 归一化正确
未来位置权重  = 0.00e+00                → 因果掩蔽正确
```

第二条尤其关键：掩码写错时右上三角会出现非零值，模型等于在训练时抄答案。

## 4 实验三：能力边界与语料频率

### 4.1 方法

用相同的温度（0.3 / 0.7）、top-k=10、固定种子，对五个不同的起始关键字各生成 60 个字符，人工判断语法正确性。

同时统计各关键字在语料中的出现次数。

### 4.2 结果

| 提示词 | 语料频次 | 生成结果（T=0.3） | 语法 |
|---|---|---|---|
| `if ` | 16,937 | `if not self._set_path is None:` | ✓ 正确 |
| `def ` | 9,387 | `def __init__(self, args):` | ✓ 正确 |
| `return ` | 9,278 | `return self._prefix_size` | ✓ 正确 |
| `import ` | 2,292 | `import the file of the precision of the default to a string in the` | ✗ 散文 |
| `class ` | 2,149 | `class String the file of the string and of the context the stack i` | ✗ 散文 |

### 4.3 分析

**（1）分界线在 5000 次左右**

出现 9000 次以上的模式，模型能写出语法正确的形式；出现 2000 次左右的，退化成自然语言。

这不是巧合：模型对每个上下文的预测能力取决于见过多少次该上下文。样本足够时，它能归纳出「`class` 后面必须跟标识符 + 冒号」这条规则；样本不足时，只能退回到「`class` 是个词，后面接点英文」——而英文散文是语料中最常见的文字形态（注释、docstring）。

**（2）`self.` 的成功也印证了这一点**

`self.` 出现 20,487 次，是语料中最高频的模式（高于 `if` 的 16,937 次）。模型生成的 `self._set_path`、`self._prefix_size` 都是真实的下划线属性命名，形态完全正确。

> **统计口径提醒**：用 `grep -o "self."` 会得到 29,194 这个偏大的数字，因为 `.` 在正则中匹配任意字符，把 `self_`、`selfs` 等也算进去了。模式频率必须用精确字符串匹配（`str.count`），否则会高估 42%。这个细节在评估「低频模式学不会」时很关键——口径错了，阈值判断就会跟着错。

**（3）高温暴露了「只知形状、不知规则」**

```
T=0.3:  def __init__(self, args):
T=0.7:  def __name__(self, and items, name=None):    ← and 是 Python 关键字
```

模型知道「参数位置该放一个词」，但不知道 `and` 不能做参数名。**这是纯统计学习的边界。**

### 4.4 一个可验证的预测

如果语料从 567 万字符扩到 2000 万（约 3.5 倍），`class` 的出现次数会达到约 7,500 次，跨过 5,000 的分界线。

**预测：届时 `class` 应能生成 `class Foo:` 这样的正确格式。**

这个预测可以在扩语料后直接检验，用于验证「频率阈值」这个解释是否成立。

## 5 局限

诚实列出这次工作没做到的部分：

**（1）分词粒度过粗**

字符级词表只有 96 个 token。模型要花大量参数去记「`d` 后面常跟 `e`」这种低级规律。同样参数量下，BPE 分词（把 `def`、`self.`、`return` 当成单个 token）能表达多得多的语义，序列长度还会缩短 2-3 倍。

**（2）语料单一且偏小**

567 万字符全部来自 Python 源码，没有自然语言、没有其他编程语言。模型学到的是「Python 的字符统计规律」，不是通用语言能力。

**（3）深度不足**

只有 2 层。论文用 6 层，更深的模型能组合出更复杂的模式。但本次实验显示加深的代价远高于加宽（+73% 时间），在 8 GB 显存的笔记本上需要权衡。

**（4）缺少基线对比**

没有和 n-gram 语言模型对比。理论上字符级 5-gram 在 567 万字符上也能达到 ppl 6-7 的水平。**没有这个对比，就无法证明 Transformer 的结构优势**——这是本次工作最大的方法论缺口。

**（5）生成质量靠人工判断**

没有自动评价指标（如语法解析成功率）。人工判断容易受个例影响。

## 6 下一步

按优先级排序：

**（1）补 n-gram 基线**（成本最低，价值最高）

用同样的数据和切分训练一个字符级 5-gram，对比 ppl。如果 n-gram 也能到 6.7，那说明参数扫描的结论需要重新审视。

**（2）扩语料至 2000 万字符**

从 GitHub 抓取主流 Python 项目源码。扩完后重跑参数扫描，验证 §4.4 的预测。

**（3）换 BPE 分词**

词表 4000-8000，把常见片段合成单 token。这一步能让同样的参数量发挥更大作用，但需要重写数据管道。

**（4）增加层数至 4-6**

在扩语料之后再做，否则只会加速过拟合。
